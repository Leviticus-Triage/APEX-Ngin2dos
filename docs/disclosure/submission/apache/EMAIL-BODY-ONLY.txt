Hello Apache Security Team,

I am reporting a denial-of-service vulnerability in mod_http2 as shipped with
httpd 2.4.68 (mod_http2 2.0.41), tested against default configuration in an

SUMMARY
-------
CVE-2026-49975 remediated empty cookie-crumb field counting, but a distinct
"fat-cookie + indexed reference" HPACK chain still causes remote memory
exhaustion.

Evidence (APEX-Ngin2dos harness, localhost Docker lab, 8 GiB cgroup):

  Run fa94b7ad — 800 connections: 800/800 bomb_ok, ~320 MB wire,
    server_down=true, oom_likely=true

  Run d6b2bce1 — 1200 connections: 879/1200 bomb_ok, ~351 MB wire,
    server_down=true, oom_likely=true, probe worst latency 15s

Contrast: empty-cookie PoC (original CVE-2026-49975 vector) is blocked on 2.4.68
with flat RSS (~52 MiB).

The 2.0.41 fix (commit 47d3100b25) addresses empty-crumb accounting but not
aggregate memory retention on the fat-cookie merge path.

I request CVE evaluation as incomplete remediation of CVE-2026-49975.
